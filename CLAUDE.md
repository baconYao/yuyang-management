# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Yuyang (宇陽科技) management system: a FastAPI + PostgreSQL backend (`backend/`), a React + Vite + Tailwind frontend (`frontend/`), Kustomize manifests for k3s (`deploy/`), and a standalone legacy CSV→PDF quotation script (`services/generate_quotation/`, not wired into the app). The domain is customers → contracts → bills (invoices/請款單). User-facing text and docs are largely in Traditional Chinese.

The root `README.md` is stale (describes only the old invoice script); trust `backend/README.md`, `Makefile` and `deploy/README.md` instead.

## Commands

### Full stack (Docker, from repo root)
- `make dev-up` / `dev-down` / `dev-logs [LOGS=api]` / `rebuild-dev` — frontend :3000, API :8000, docs at :8000/docs (Scalar, not Swagger)
- `make seed-data-dev` — runs `python -m scripts.generate_fake_data` inside the api container
- `make dev-shell-api|dev-shell-db`; `prod-*` equivalents use `docker-compose.prod.yml`

### Backend (from `backend/`, uv-managed, Python 3.12)
- Install: `uv pip install -e ".[dev]"`
- Run: `uvicorn app.main:app --reload`
- Test all: `pytest`; single test: `pytest tests/test_bills_api.py::test_name -v`
- Lint/format (CI runs both, must pass): `uv run ruff check .` and `uv run ruff format --check .`
- Typecheck: `pyright` (covers `app/` only)
- Migrations: `alembic revision --autogenerate -m "msg"`, `alembic upgrade head`

### Frontend (from `frontend/`)
- `npm run dev`, `npm run build` (runs `tsc` first), `npm run lint` (zero warnings allowed). No test runner is configured.

## Architecture

**Backend layering** (`backend/app/`): `api/v1/*.py` routers (registered in `api/v1/__init__.py`) → `services/*_service.py` classes (take an `AsyncSession`, hold all business logic; wired via `get_*_service` dependencies in `api/`) → SQLModel tables in `database/models/`. Pydantic request/response schemas live separately in `api/schemas/`. Everything is async (asyncpg in prod).

**Bills** are the most intricate domain: `BillService` generates bill numbers of the form `B-<5-letter contract suffix>-<NN>` derived from the contract number (`C-YYYY-MM-XXXXX`), computes amounts/tax from line items (stored as JSONB), enforces status transitions (`InvalidStatusTransitionError`), and PDFs are rendered with WeasyPrint + Jinja2 templates in `app/pdf/` (`generate_pdf_bytes`). `bill_number` is the primary key (no integer id).

**Schema management has two paths — keep them in sync:**
- On startup, `lifespan_handler` runs `run_migrations()` (Alembic `upgrade head`, retrying up to 30×2s for Postgres) unless `RUN_DB_MIGRATIONS=false`. Tests set that to false in `tests/conftest.py`.
- `create_db_tables()` / `SQLModel.metadata.create_all` can also create tables, so a DB built that way has no Alembic version — run `alembic stamp head` (see `backend/README.md`).
- Any new model must be imported in both `migrations/env.py` and `database/session.py::create_db_tables` (and `tests/conftest.py`), otherwise metadata won't see it. Migration files in `migrations/versions/` are hand-named, not just hashes; review autogenerated output, especially enum changes.

**Tests** use in-memory SQLite (`aiosqlite`) via fixtures in `tests/conftest.py`, overriding `get_session`; `asyncio_mode = auto`. So Postgres-only features (JSONB, enum alterations) are not exercised by tests.

**Config:** `app/config.py` (`db_settings`, pydantic-settings) reads `POSTGRES_*` and `RUN_DB_MIGRATIONS` from env / `backend/.env`.

**Frontend:** pages in `src/pages/`, shared modals/components in `src/components/`, axios API wrappers in `src/services/` (`customerApi`, `contractApi`, `billApi`), status-label helpers in `src/utils/`. `/api` is proxied to the backend by Vite in dev and by `nginx.conf` (`http://api:8000`) in the container.

**Deploy:** `deploy/` has Kustomize `base/`, `components/`, `overlays/` (namespace `yuyang`); secrets (GHCR pull secret, `postgres-secret`) are created manually, never committed. CI (`.github/workflows/`) runs backend ruff + pytest, and builds/pushes images to GHCR.

## Gotchas
- `ruff` is configured with `target-version = "py314"` while the project and CI use Python 3.12; avoid 3.13+-only syntax.
- Dev compose mounts `backend/app`, `scripts`, `alembic.ini` and `migrations` into the container for hot reload; dependency changes need `make dev-build`.
